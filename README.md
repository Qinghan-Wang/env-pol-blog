# Thirsty Algorithms in the Desert

A single-page environmental policy blog on generative AI data centers and the water policy
dilemma in Phoenix and Mesa, Arizona.

**Title:** *Thirsty Algorithms in the Desert: Generative AI Data Centers and the Water Policy
Dilemma in Phoenix and Mesa, Arizona*

## What is in this repository

```
index.html                                    the whole blog (HTML + CSS + a few lines of JS)
.nojekyll                                     tells GitHub Pages to serve the files as-is
assets/
  images/cover-phoenix-aerial.jpg             cover photograph
  images/mesa-data-center-cooling-tower.jpg   cooling-tower photograph (Mesa, Arizona)
  images/saguaro-cactus-arizona.jpg           desert photograph
  figures/figure1-water-energy-flowchart.svg  Figure 1 - author-made flow diagram
  figures/figure2-water-use-estimates.svg     Figure 2 - author-made data-card comparison
```

No build step, no framework, no external fonts or scripts: every page asset is served from this
repository, so the blog renders offline and loads quickly.

## Structure of the article

Introduction · 1. Why AI Data Centers Need Water and Energy · 2. Phoenix and Mesa: Growth in a
Water-Constrained Region · 3. The Environmental and Social Questions Behind the Numbers ·
4. What Existing Policies Can and Cannot Do · 5. Three Policy Recommendations for Arizona ·
Conclusion · References

* Length: about 3,360 words of running text; 3,505 with section headings and about 3,590 including
  figure captions. The reference list is additional. Within the required 3,000–4,000 word range.
* All in-text references are embedded hyperlinks, with a full reference list at the end.
* Both figures are original diagrams created by the author, with data sources cited in the
  captions. No third-party charts are reproduced.
* Every image carries a title, a source and a licence line.

## Publishing with GitHub Pages

1. Create a **public** repository and upload the contents of this folder to its root.
2. Go to **Settings → Pages**, set **Source: Deploy from a branch**, **Branch: main**, **Folder: / (root)**,
   then **Save**.
3. Wait one to two minutes. The site appears at `https://<username>.github.io/<repository>/`.
4. Open that URL in a private/incognito window to confirm it is publicly readable without logging in.
